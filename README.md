# Pay_zfb 支付宝支付模块 · 安全评估与整改

本仓库收纳对 `Pay_zfb` 支付宝电脑网站支付模块的**代码安全与可行性评估**，
以及配套的**安全入账参考实现**。

> 🔴 **重要提示**
> 被评估的原始代码中硬编码了**真实的支付宝应用私钥**（2048 位 RSA）与**数据库明文口令**。
> 更进一步，本次评估证实：**同一份私钥已在公开仓库
> [`LG1987/Pay_zfb`](https://github.com/LG1987/Pay_zfb) 的 `master` 分支上暴露，
> 最早提交可追溯至 2020-05-26，暴露时长超过 5 年。**
> 该私钥必须按**已完全泄露**处置。
>
> 本仓库**不包含**任何原始密钥材料，报告中仅以 DER 指纹标识。
> 如果你的环境仍在运行该代码，请**立即**执行[整改工单](docs/代码安全与可行性评估报告.md)中的
> **WO-01（重置支付宝应用密钥）** —— 这是唯一有效的止损手段。
> 清洗仓库历史（WO-06）只能减少后续被抓取，**不能**使旧密钥失效。

## 评估结论摘要

共发现 **20 项问题**：🔴 P0 严重 8 项、🟠 P1 高 4 项、🟡 P2 中 8 项。

### 三条核心结论

**一、存在可直接刷单的越权入账漏洞，无需任何认证。**
全模块零鉴权。查询接口 `doGet` 在不校验 `trade_status` 的前提下调用入账，
且入账对象由 URL 参数 `UserNo` 指定。攻击者自助下单后不付款，
直接发一个 HTTP GET 即可白拿额度。

**二、支付宝应用私钥明文硬编码在 6 处，应视为已泄露。**
私钥、`appid`、服务商 PID 三者齐备，足以冒充该商户调用支付宝开放平台接口。
已通过 DER 解析确认其为结构完整、未加密的 PKCS#8 私钥。

**三、项目不具备继续开发的技术基础，建议重写而非改造。**
缺少构建文件与全部依赖；`web.xml` 声明了 2 个不存在的 Servlet；
技术栈（Servlet 2.5 + 裸 JDBC）与现有 Spring Boot 3 体系不兼容。

### 可行性判定

| 用途 | 结论 |
| --- | --- |
| 直接运行 / 部署 | ❌ 不可行 |
| 生产系统继续使用 | 🔴 高危，应立即止损 |
| 学习支付宝接入 | ⚠️ 反面教材 |
| 二次开发基座 | ❌ 不建议 |
